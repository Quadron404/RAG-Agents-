## PROMPT-2 — Dependency and execution architecture map

**Concrete dependency graph (browser → edge → backend):**

1. Browser entry: `Frontend/src/main.tsx` → `App.tsx`.
2. `App.tsx` bootstrap calls `useAuth().bootstrap()` (`src/auth.ts`), then on `authenticated` calls `useCore().connect()` → WebSocket `wsUrl(/ws/:userId)` (same-origin in prod; `VITE_BACKEND` override in dev).
3. `Frontend/src/core.ts`:
   - `apiFetch(path)` → same-origin `fetch` with `credentials: "include"` + `x-rag-csrf` CSRF header. Used for `/threads`, `/threads/:id/messages`, `/auth/settings/*`, `/computer/start|stop`, `/sysinfo`, `/session/active-thread`, `/routines/*`.
   - `send()` → Worker-native SSE: POST `/threads` (create) then POST `/threads/:id/messages` (stream). Chat is Worker-owned; WebSocket is only for computer/screen.
4. Worker `src/index.ts` `fetch`:
   - `/auth/*` (login/callback/session/logout/timezone/developer-mode/reset) — handled at edge, session cookie (`rag_session`, HttpOnly).
   - `/internal/*` → `handleInternal` (requires `x-rag-internal-token`).
   - `/health` → proxied unauthenticated to `BACKEND_ORIGIN`.
   - chat paths (`/threads*`, `/chat/status`) → `handleChatRoutes` (Worker-native, D1 + AI Search).
   - `/routines/connectors/approvals*` → Worker-native approval cards (D1).
   - `isProxyPath` (`/threads`, `/computer`, `/ai`, `/sysinfo`, `/file`, `/cdp`, `/screen`, `/websockify`, `/ws`, `/routines`, `/auth/*`) → `proxyApi` → `buildUpstreamRequest` (strips spoofable headers, injects `x-rag-internal_token` + identity headers) → fetch to `BACKEND_ORIGIN`.
   - Fallback: `env.ASSETS.fetch(request)` (SPA).
5. `worker/src/scheduler.ts` `scheduled` handler → `runScheduler(env, now)` every minute (Cron `* * * * *`). Materializes due routines in D1, executes them at the edge via `executeRoutine` (Groq `openai/gpt-oss-20b`), runs summaries. Worker-native; does not require Codespace awake.
6. Backend `backend/app/main.py` (FastAPI, SQLite `rag.db`): `/health`, `/auth/*`, `/gmail/*`, `/threads*`, `/session/active-thread`, `/computer/*`, `/ai/computer/*`, `/sysinfo`, `/file`, `/cdp/*`, `/routines/*` (edge client `RoutineClient`), `/internal/summaries/run`, `/internal/routines/execute`, `/internal/mail/execute`, `/internal/connectors/*`. Auth: `x-rag-internal_token` gateway OR session cookie; client-supplied `user_id` never trusted.

**Data contracts:**
- Edge session cookie ↔ `sessions`/`users` D1 tables (HMAC of token, never plaintext).
- Proxy identity headers: `x-rag-user-sub` (authoritative subject), `x-rag-user-email`, `x-rag-user-email-verified`, `x-rag-user-name`, `x-rag-user-picture`. Stripped from client if spoofed (`src/proxy.ts`).
- Routines: edge owns D1 `routines`/`routine_runs`; backend is a thin client via `/internal/routines/*`.

**Duplicated responsibilities:** Connector approvals exist both at the edge (`worker/src/connector-approvals.ts`, Worker-native `/routines/connectors/approvals*`) and in the backend (`backend/app/main.py` `/internal/connectors/*`, `/routines/connectors/*`) backed by `connectors/registry.py`. The edge path is the approved flow (Pending Allow/Deny card → edge executes); the backend path duplicates creation/decision. Worker/backend separation is preserved by design (edge = schedule/identity authority; backend = computer/work), but connector approvals are implemented twice.

**Preserved:** authentication, thread restoration (`/session/active-thread` + localStorage hint), memory/history (Worker D1 + AI Search), provider selection (6 providers), computer connectivity (WebSocket + `/computer/*`), files (`/file`), approvals, routines.
