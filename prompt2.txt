PROMPT 1: Authentication, onboarding, and protected application shell

FEATURE DESCRIPTION AND TEST OBJECTIVE
FEATURE MAP
RAG Agents is a Google-authenticated workforce app. The Cloudflare Worker owns OIDC, D1 sessions, CSRF, and the frontend shell. Gmail consent is a separate grant. BROWSERLESS JOURNEY

REPAIR TARGET
If a test bypass exists, remove or isolate it from production without weakening normal auth. Fix session, CSRF, cookie, redirect, loading, and error-state defects at their root. Do not add a public bypass to make testing easier. Verify account ownership and protected WebSocket routes as well as HTTP.

PROMPT 2: Persistent channels, shared memory, and one unified Chief chat

FEATURE DESCRIPTION AND TEST OBJECTIVE
FEATURE MAP
The product must have one always-available Main channel and focused project channels, all using the same visible Chief assistant and chat canvas. Channels organize work; they are not separate bot identities. User-level memory may be shared across channels, while raw project transcripts, files, tasks, and private decisions remain channel-scoped unless explicitly shared. The current Worker ConversationRow has no channel_id and migration 0003 creates conversations without a channel entity; migration 0004's word channel refers to conversation summaries, not a real channel table.

BROWSERLESS JOURNEY

6. Test deep links, browser back/forward, deleted channels, empty channels, and concurrent channel switching while a response streams.

REPAIR TARGET
Implement the real D1 channel entity and safe migration if absent. Preserve legacy conversation IDs and attach them to Main. Add owner-scoped APIs and server-authoritative metadata. PROMPT 6: Tasks, routines, scheduling, and notifications

FEATURE DESCRIPTION AND TEST OBJECTIVE
FEATURE MAP
The Tasks surface contains one-off Chief work and recurring routines. The Worker Cron scheduler is intended to materialize due runs in D1, preserve them while the Codespace is stopped, wake the Codespace when configured, and dispatch idempotently. A saved routine is not the same as an executed run. Times must respect the user's IANA timezone and daylight-saving rules.

BROWSERLESS JOURNEY
1. Create a one-off task and verify it appears in the task list and originating channel.
2. Create a synthetic daily routine with a test time, inspect the saved timezone and next run, then pause, resume, edit, and delete it.
3. Test a weekly and monthly recurrence, month-end behavior, and a daylight-saving transition using a safe test clock or test fixture.
4. Inspect queued, running, delayed, completed, rejected, and failed states. Simulate an unavailable backend or Codespace and verify the run remains queued rather than disappearing.
5. Verify duplicate cron ticks do not execute the same run twice.
6. Confirm completion and approval notifications deep-link to the right task and channel, respect quiet hours, and do not duplicate.

REPAIR TARGET
Fix task persistence, recurrence preview, run leases, retry/backoff, cancellation, and truthful notification state. Never claim a scheduled task ran because its card was created. Do not send real notifications or run destructive tasks against the owner's account.
